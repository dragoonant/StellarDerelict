# 40 — The Molt AI (M4)

`src/ai/molt/` plays the Molt seat. It is pure and deterministic: `(state, tier, seed)` gives one `Action`. It reads
`view(state, 'molt')` only (never the RNG, never the bag order), keeps no memory between calls (every call re-plans the
phase from the board, so a reopened save plays the same), and reads no clock unless one is injected.

## Entry point and tiers (`src/ai/tiers.ts`)

`chooseMoltAction(state, tier, seed | rng, opts?) -> Action`, `tier` in `recruit | regular | veteran`.

| Tier | Plays as | Deliberate limits |
|---|---|---|
| `regular` | `moltPolicy` from `src/ai/scripted.ts`, unchanged | the scripted bot of the balance record |
| `veteran` | the utility AI below | none |
| `recruit` | the utility AI | never reveals as a group (a ping reveals alone once a Warden is within 5 steps), scores every strike square alike (ignores flanks), idles each stalker or ping with probability 0.25 per phase (seeded from state seed, round and unit id), no ganging bonus |

`?bot=recruit|regular|veteran` picks the tier in the client; `?bot=random` keeps the random bot. The Briefing's
**Difficulty** choice (default Regular) is saved in `setup.options.difficulty`; the URL parameter overrides it.

## Decision kinds

A call classifies the board into one of five kinds; each has one policy in `POLICIES: Record<DecisionKind, Policy>`.
`ACTION_KIND: Record<Action['type'], DecisionKind>` and `PENDING_KIND: Record<Pending['kind'], DecisionKind>` are
exhaustive maps, so a new action type or pending kind does not compile until it is given a kind.

| Kind | Actions | What the policy does |
|---|---|---|
| `arrive` (pending) | `arrive` | scores each open duct (below) and takes the best |
| `pingMove` | `move`, `door` by a ping | picks a hold or approach square among those the ping may legally reach, avoiding every seen square |
| `pingReveal` | `reveal` | reveals when the group can strike (below), or when waiting no longer pays |
| `stalkerAct` | `move`, `door`, `tear`, `melee` by a stalker | one-ply over the stalker's reachable squares, then the first step to the best one; melee when it beats moving |
| `endPhase` | `endPhase` | score 0; chosen when no candidate scores above 0.05 |

Candidates from every kind (except `arrive`, which is pending-only) are scored on one scale and the best wins; ties are
broken by a seeded jitter. If the best action is not legal, or the policy throws, the AI falls back to a random legal
action and counts it (`aiStats.fallbacks`, read by the bench).

## Phase plan (recomputed each call, cached by board signature)

- **Threat map.** For each watching Warden with shots left (`heat < lock`, plus held CP: each adds `lock - heldCpHeat`
  shots), the squares it sees within `repeater.maxRange`, with `hitChance`-style kill odds. A stalker finishing a move,
  door or tear on such a square dies with probability `1 - prod(1 - p)`.
- **Exposure map.** Squares with line of sight to a living Warden: what the Warden phase will shoot or burn. A stalker or
  ping that ends the phase there pays `E` (below), more inside the scorcher's range with charges left.
- **Routes.** The squad's shortest route to its objective (archive console until the core is taken, then the airlock),
  with the Warden's heading on each square; `routeSeen(s)` counts route squares from which `s` would be seen.
- **Focus.** The Warden with the best target value `T(w)`: carrier, then Tech while the archive is sealed, Sergeant,
  breached, not watching, repeater locked, isolated (no Warden within 3), and the number of free flank squares.
- **Ganging.** `attackers(w)` counts Molt units (stalkers now, pings that could reveal now) that can reach a strike
  square of `w` with 1 AP to spare. A first hit on an unbreached Warden is worth more when `attackers(w) >= 2` (A-1).

## Features and weights (veteran; initial values, the bench decides)

| Feature | Weight |
|---|---|
| Lethal hit on a Warden: breach `4`, destroy `10`, carrier destroyed `+14`, Tech (archive sealed) `+3`, Sergeant `+3`, Scorcher `+2` | value of a win in melee x its odds (`query.meleeOdds`, flank from the real facing) |
| Stalker lost | `-3` per stalker x kill probability (watch en route, melee loss) |
| Flank square (not the Warden's front square) | already inside the melee odds; plus `+1.2` for avoiding the front arc |
| Ganging, two or more attackers on an unbreached Warden | first-hit value x `1.5` |
| End-phase exposure `E` | `-3 x P(die in the Warden phase)`; adjacent to a Warden counts as seen |
| Bunching in a scorcher burst (adjacent friend, scorcher sees square, charges left) | `-1.5` per adjacent friend |
| Door: closed and unsealed | `+1 AP`; sealed and a ping `blocked`; sealed and a stalker `4.5 AP` (expected tear plus move); a door action that would force a ping to reveal in sight of a Warden is scored from `step` on a clone |
| Body-block (carrier's route ahead, within 10 squares, not in a Warden's arc) | `+0.8` |
| Ping hold square | `+` closeness to the route (best at 2..4 steps), `-2.5 x routeSeen`, `-6` if any Warden can see it after one turn |

Arrival duct: `-(path distance to the route ahead of the carrier, or to the squad before the core)`, `-0.4 x distance to
the nearest other ping` (concentrate), `-` unsealed-door detours; before the core is taken the objective route is the
archive spine, after it the way home to the airlock.

**Group reveal.** A ping reveals when, counting its stalkers and every stalker that can also reach the same Warden's
strike squares this phase, the expected lethal hits on one Warden reach `1.6` (`0.9` if breached), or when the carrier is
within 10 steps of the airlock, or in the last two rounds, or when the ping has no hidden square to stand on.

## Cost budget

Average decision <= 30 ms, worst <= 250 ms on the cloud container (measured by the bench); a whole AI-vs-scripted game
<= 1.5 s. An injected `clock` and `budgetMs` stop optional lookahead early; with no clock the AI is fully deterministic.

## Worker (client)

`src/ai/worker.ts` runs `chooseMoltAction` off the main thread; `src/ai/workerClient.ts` wraps it. If the worker cannot
start or errors, the wrapper logs one console warning and runs the same function on the main thread.
